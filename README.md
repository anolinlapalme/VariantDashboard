# VariantDashboard

An in-house dashboard for interpreting germline variants in hereditary cancer genes. It brings together, for any variant, the data a clinical scientist looks up in ClinVar, gnomAD, BRCA Exchange, LOVD, UCSC, MaveDB and the ENIGMA specifications, and fills in as much as possible for variants nobody has seen before. It is a repository of data, not a classifier: every value comes from a named, dated source or a fixed calculation, and nothing is generated by a language model.

The first gene is **BRCA1** (NM_007294.4, GRCh38). The other genes of the panel are to follow.

## What the page shows

| Section | Content |
|---|---|
| Summary | Variant names (HGVS, legacy BIC, genomic, rsID), location, truncation and NMD facts, key values at a glance, data flags, links out |
| Population | gnomAD v4.1 counts, filters and FAF (one rule for the whole page: joint grpmax FAF95), genetic-ancestry groups, read depth, sequence context, NCBI ALFA, links to RGC Million Exome, All of Us and TOPMed BRAVO |
| French-Canadian | Quebec founder variants (Behl et al. 2020), CARTaGENE link, local counts |
| Clinical | ClinVar record and every submission, ENIGMA via BRCA Exchange, reduced penetrance, multifactorial likelihoods, tumour-pathology and CanRisk likelihood ratios, Fanconi anaemia cases |
| Literature | Papers indexed for the variant (ClinVar citations, LitVar2, Ensembl), titles from PubMed, listed and not summarised |
| Pedigree | Family drawing, co-segregation likelihood ratio (Mohammadi et al. 2009), Easton 2007 family-history factors, CanRisk export |
| Splicing | SpliceAI, MaxEntScan, predicted transcript events, SpliceVault mis-splicing events seen in 300K RNA-seq samples, natural isoforms, published RNA results |
| Functional | MaveDB multiplexed assays with their calibrations, ENIGMA Table 9 and per-study results |
| In silico | BayesDel, REVEL, AlphaMissense, CADD, FoldX ΔΔG (mutfunc), substitution scores |
| Gene, Protein, Conservation, Structure | Gene and protein views, ortholog alignment with the species tree, experimental structure with optional mutant models (Mol*) |
| Changes | What changed in the sources since the previous data release, variant by variant; doubles as a reclassification queue |
| Record | Laboratory classification with two-person sign-off, notes, dated snapshots, watch list, in-house data |

Sections can be hidden (×), reordered (drag ⠿, or the **Layout** button) and folded; the layout is remembered per browser. The interface switches between English and French (**EN | FR** in the header).

ACMG/AMP and CanVIG-UK code suggestions exist in the code but are switched off (`criteria: false` in the `CFG` block of the page). Published expert-panel codes (ENIGMA Tables 4 and 9) are still shown as data.

## Quick start (one computer)

Requirements: Python 3.8 or later (standard library only) and a recent browser.

```bash
python3 build_brca1_db.py          # writes brca1-data.js next to the script (first run 45-90 min, later runs 10-20 min)
open brca1-variant-explorer.html   # or double-click it
```

Without `brca1-data.js` the page still works and queries every source live. With it, every reviewer sees the same values for the same dated release, and only variants missing from the release are queried live.

## Monthly data release

`build_brca1_db.py` downloads the public sources, annotates every variant in the release with Ensembl VEP, and writes one dated file, `brca1-data.js`. The release covers every gnomAD and ClinVar BRCA1 variant, every possible SNV in the coding sequence and the 20 intronic bases next to each exon, every saturation-genome-editing SNV, and every variant named in the ENIGMA tables, BRCA Exchange and the French-Canadian founder list. Downloads are cached in `.brca1-build-cache/`, so interrupted runs resume and later runs only fetch what changed.

Each build also compares the new release with the previous one and lists, per variant, what changed: ClinVar classification, review status and submissions, the ENIGMA classification and Table 9 code, gnomAD counts and FAF (flagged when it crosses 2×10⁻⁵, 10⁻⁴ or 10⁻³), SGE scores and newly indexed papers. The list appears in the page (**Changes**) and as a CSV in `brca1-releases/`, which also keeps a small digest of every release.

```bash
python3 build_brca1_db.py --reported private/brca1_reported.csv   # also writes the reclassification queue for your reported variants
python3 build_brca1_db.py --changes-only --previous old/brca1-data.js   # recompute the change list without downloading anything
python3 build_brca1_db.py --help
```

The reported-variants file needs an `hgvsc` column and can have `classification`, `date` and `sample` columns (see `examples/reported_variants_example.csv`). The page's in-house CSV works as is. Keep such files in `private/`, which git ignores.

Deployment notes:

- Run it on a hospital machine with HTTPS (`--cert/--key`, or behind the hospital's HTTPS proxy with `--secure-cookie`). Without TLS, passwords and records cross the network unencrypted.
- To sign people in with the hospital's single sign-on, put the server behind a proxy that sets a header and start it with `--trust-header X-Remote-User`. Accounts must still exist (`adduser`). Only safe when the proxy is the only way to reach the server.
- The database holds patient-related information (pedigrees, sample identifiers). Keep it on hospital storage, back it up with the laboratory's other records, and follow the institution's privacy rules (Loi 25). `.gitignore` excludes `*.sqlite`, `backup*.json` and `private/`.

## Files

| File | Purpose |
|---|---|
| `brca1-variant-explorer.html` | The page: one self-contained file (scripts for Mol*, Nightingale and SheetJS load from CDNs) |
| `build_brca1_db.py` | Builds the dated data release `brca1-data.js`, the change list and the reclassification queue |
| `brca1_server.py` | Optional shared store and web server for the laboratory |
| `examples/` | In-house data template and a reported-variants example (made-up identifiers) |
| `tests/` | `python3 -m unittest discover tests`: shared-store rules and change detection |

Not in the repository: `brca1-data.js` (about 70 MB, rebuilt monthly), the build cache, `brca1-releases/`, the store database and anything under `private/`.

## Data sources

Ensembl (VEP, Compara), gnomAD v4.1, NCBI ClinVar (aggregate records, submissions, citations), BRCA Exchange (ENIGMA classifications), ClinGen CSpec registry (ENIGMA BRCA1/2 VCEP v1.2 specifications and supplementary tables), MaveDB (Findlay 2018, Starita 2015/2018, Adamovich 2022), UniProt, AlphaFold DB, PDBe and RCSB, SpliceVault (Dawes et al. 2023, via the file Ensembl distributes for its VEP plugin), NCBI ALFA, NCBI LitVar2 and PubMed, Behl et al. 2020 (French-Canadian founders), Spurdle et al. 2014, Mohammadi et al. 2009, Easton et al. 2007, Lindeboom et al. 2016 (NMD rules). CARTaGENE, the RGC Million Exome browser, All of Us and TOPMed BRAVO are linked, not copied. The generated release is not committed: each source's terms of use apply to it. The page shows the version and retrieval date of every source next to the values.

## Structure models

The mutant models embedded in the page (8 variants in the BRCT and RING domains) were built offline by a script not included here: PDBFixer side-chain placement, then OpenMM (AMBER14, OBC2) minimisation of the 6 Å shell, contacts and burial by Biopython. Known limits: the wild type is the deposited structure without minimisation while the mutant shell is minimised, so part of a lost or gained bond can come from the minimisation; there is no rotamer search or backbone change; and the structural flags have not been calibrated against assay data. Treat them as illustrations.

## Status

- BRCA1 only; gene-specific settings are still in the page.
- French translation, first pass: the interface, section and table titles, and the new features. Explanations behind the ⓘ buttons and some generated sentences are still in English.
- The SpliceVault and ALFA readers were tested against local test files built in the same formats, not yet against the live files.
- For use by qualified laboratory staff, alongside the laboratory's validated procedures. It does not classify variants and is not a medical device.
